# Подкаст «Стоит попробовать»

Публичные адреса: [страница](https://brav.in/podcast-ntt/) и [RSS](https://brav.in/podcast-ntt/feed.xml). Каталог выпусков хранится в `episodes/`, один JSON на выпуск. Имя JSON соответствует имени MP3: `001.json` → `001.mp3`; `stableId` сохраняется внутри записи и не используется как имя файла. Снимок исходного RSS находится в `migration/source.xml`, а подтверждённые соответствия аудио — в `migration/mapping.json`.

## Первоначальная миграция

```bash
npm run podcast:import
npm run podcast:audit -- --audio-root "$HOME/Downloads/_Render"
npm run podcast:migrate -- --audio-root "$HOME/Downloads/_Render"
```

`--audio-root` обязателен: автоматического поиска между Downloads и Яндекс Диском нет. Аудит не меняет MP3 и сохраняет относительные пути. Миграция останавливается при пропусках или неоднозначностях. Команда миграции остаётся прежней, параметр `--skip` не нужен: согласованные завершённые выпуски пропускаются без сетевой проверки. Локальные проверки архива выполняются всегда; новые и неподтверждённые выпуски проходят полную проверку, а отсутствие state приводит к полной проверке. Такой пропуск не обнаруживает последующее внешнее удаление или изменение объекта в облаке. VK Cloud задаётся переменными `VK_CLOUD_ENDPOINT`, `VK_CLOUD_REGION`, `VK_CLOUD_BUCKET`, `VK_CLOUD_PUBLIC_BASE_URL` и стандартными переменными AWS SDK для учётных данных.

При временном сетевом сбое или публичном HTTP 404 на этапах `HEAD`, `Range` или полного `GET` миграция делает до трёх попыток с паузами 1 и 2 секунды. Каждая попытка открывает MP3 заново; перед повторной загрузкой проверяется SHA-256 уже существующего объекта, поэтому исправный объект не загружается повторно. После успешной публичной проверки запись состояния и JSON выпуска выполняются только один раз. Ошибка доступа, неверные MIME/размер/SHA и другие HTTP-ошибки останавливают миграцию без повтора. Постоянный публичный 404 также останавливает миграцию и не обновляет JSON или state. При отказе JSON и state неуспешного выпуска не обновляются; защитный механизм может сбросить глобальный флаг готовности каталога.

## Новые выпуски

```bash
npm run podcast:publish -- \
  --audio "$HOME/Yandex.Disk.localized/Work/Projects/NeedToTry/_Render/129.mp3" \
  --publish-at "2026-10-27T11:00:00+04:00"
```

В MP3 обязательны `TIT2` (название) и `TIT3` (полное описание). Дата всегда задаётся явно и со смещением; поля даты ID3 не используются. Локальный MP3 не изменяется, перемещается или удаляется. Команда создаёт техническое состояние в `.podcast-publish/`, переиспользует уже загруженный объект, записывает JSON, затем включает только этот JSON в commit и отправляет его в `master`. Git-конфликты и посторонние изменения останавливают команду.

Объекты хранятся в корне бакета и имеют имя локального файла: `000.mp3`, `001.mp3` и т. п. Повторная публикация того же имени проверяет содержимое и при изменении автоматически заменяет объект с тем же URL; неизменённый объект переиспользуется. SHA-256 хранится в технических метаданных. GUID, даты и внутренние `stableId` выпуска сохраняются при редактировании. `.podcast-publish/` позволяет безопасно продолжить прерванную подготовку, но не разрешает подменять подготовленный JSON. Уже скачанные копии у слушателей не заменяются автоматически, а между заменой объекта и deployment RSS возможен промежуток со старыми техническими полями. Сборка сайта не зависит от локального состояния, аудиоархива или S3.

## Публикация и перенос

GitHub Actions собирает один Pages artifact с HTML и RSS и публикует его одним deployment. Расписание: `10 3,7,11,15,19,23 * * *` UTC, то есть примерно раз в четыре часа и около 11:10 по Самаре. Расписание GitHub может задерживаться или пропускаться; будущие выпуски скрыты до даты начала сборки, а публикация в приложениях происходит независимо.

После проверки полного архива, публичного доступа, `HEAD`, Range, размера, MIME, воспроизведения и перемотки новый RSS можно передавать в mave для HTTP 301 на `https://brav.in/podcast-ntt/feed.xml`. GUID не меняются. Старый хостинг и redirect с migration-тегом следует сохранять минимум четыре недели и не считать перенос подтверждённым до проверки старых подписок и карточек площадок.
