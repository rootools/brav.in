# brav.in

Сайт-визитка Антона Бравина. Markdown-файлы — источник содержания, а `templates/page.html` и `styles/main.css` — источник оформления. `dist/` генерируется автоматически и не редактируется и не коммитится.

## Локальная работа

Требуется Node.js 20 или новее.

```bash
npm ci
npm run build
npm run check
npm run preview
```

`npm run preview` запускает локальный просмотр каталога `dist/` на порту 8080.

## Исходники и адреса

Главная находится в `index.md`, публикации — в `_posts/talks/`, ошибка — в `404.md`. Для публикации `YYYY-MM-DD-slug.md` генератор создаёт основной адрес `/YYYY/MM/DD/slug/` и совместимый старый адрес `/YYYY/MM/DD/slug.html`. Canonical и sitemap используют только основной адрес.

Ресурсы хранятся в `assets/`, `me.JPG` и `favicon.png`. Результат сборки — обычный статический HTML/CSS; JavaScript-генератор посетителю не передаётся.

Текст, заголовки, подписи и код используют JetBrains Mono из Google Fonts, а при недоступности Google Fonts — системный моноширинный шрифт.

## Публикация

GitHub Actions запускает `npm ci`, сборку и проверки при push в `master`, для pull request выполняет только проверку, а успешный push публикует единый Pages artifact из `dist/`. Расписание подкаста — `10 3,7,11,15,19,23 * * *` UTC; точное время появления не гарантируется. В настройках репозитория Pages должен быть выбран источник **GitHub Actions**, домен — `brav.in`, HTTPS — включён.

Подробная инструкция миграции и публикации подкаста находится в [`podcast-ntt/README.md`](podcast-ntt/README.md). Первичная миграция явно использует `~/Downloads/_Render`, последующие выпуски — явно переданный путь из Яндекс Диска. Команда миграции остаётся прежней, `--skip` не нужен: согласованные завершённые выпуски пропускаются без сети, а локальные проверки архива сохраняются; новые, неподтверждённые и записи без state проходят полную проверку. Пропуск не обнаруживает последующее внешнее удаление или изменение объекта в облаке. Временный публичный HTTP 404 после загрузки повторяется до трёх раз с паузами 1 и 2 секунды; постоянный 404 не обновляет JSON/state, а защитный механизм может сбросить глобальный флаг готовности. Для нового выпуска обязательны ID3 `TIT2`, `TIT3` и дата `--publish-at` со смещением. Для редактирования существующего выпуска достаточно передать `--audio`: его имя определяет выпуск, а GUID и даты сохраняются; изменённый MP3 автоматически заменяет объект по тому же URL. MP3 не удаляются и не редактируются; техническое состояние загрузчика хранится в `.podcast-publish/` и не попадает в Git. Адреса подкаста: `/podcast-ntt/` и `/podcast-ntt/feed.xml`.

Откат выполняется возвратом предыдущего коммита и повторной публикацией workflow; перед переключением Pages следует сохранить исходный commit и настройки.
